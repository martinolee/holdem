# Hold'em

로그인 없이 참가하는 노리밋 텍사스 홀덤입니다. Cloudflare Workers와 Durable Objects 위에서 돌고, 무료 플랜으로 운영할 수 있습니다.

- 첫 화면이 **대기실**입니다. 열려 있는 방이 보이고, 아무 방이나 골라 빈 자리에 앉을 수 있습니다.
- 방은 대기실에서 만듭니다. 이름을 정하고, 원하면 **비밀번호**를 걸 수 있습니다. 비밀번호를 건 방은 목록에 자물쇠만 보입니다.
- 방 주소(`/t/k7m2`)를 보내면 대기실을 거치지 않고 바로 들어올 수 있습니다. 잠긴 방이면 이때도 비밀번호를 묻습니다.
- 테이블 하나에 최대 6명이 앉습니다.
- 서버가 딜러를 맡습니다. 각 플레이어에게는 자기 카드만 보내고, 덱과 다른 사람의 카드는 쇼다운 전까지 서버 밖으로 나가지 않습니다.
- 새로고침하거나 다시 들어와도 같은 브라우저면 같은 자리로 돌아옵니다.

## 필요한 것

- Node.js 22 이상
- Cloudflare 계정 (무료 플랜으로 충분)

## 로컬에서 실행

```bash
npm install
npm run dev
```

`http://localhost:8787`을 열면 대기실이 뜹니다. '방 만들기'로 방을 하나 만들고, 그 주소를 다른 브라우저(또는 시크릿 창)에서 열면 다른 플레이어로 들어옵니다. 같은 브라우저의 탭은 같은 플레이어로 취급됩니다.

턴 시간을 줄여서 시험하려면 다음과 같이 실행합니다.

```bash
npx wrangler dev --var TURN_SECS:6
```

## 배포

```bash
npx wrangler login     # 처음 한 번, 브라우저에서 Cloudflare 계정 승인
npm run deploy
```

배포가 끝나면 `https://holdem.<계정 서브도메인>.workers.dev` 주소가 출력됩니다. 처음 배포하는 계정이면 workers.dev 서브도메인을 정하라는 안내가 먼저 나올 수 있습니다. 이 주소를 열고 '링크 복사'로 테이블 주소를 보내면 됩니다.

`npm run deploy`는 배포 전에 클라이언트 번들(`public/app.js`)을 자동으로 다시 빌드합니다(`wrangler.jsonc`의 `build.command`).

## 테이블 규칙 바꾸기

`wrangler.jsonc`의 `vars`를 고치고 다시 배포합니다.

| 변수 | 기본값 | 뜻 |
| --- | --- | --- |
| `SB` | 10 | 스몰 블라인드 |
| `BB` | 20 | 빅 블라인드 |
| `BUYIN` | 2000 | 처음 앉을 때와 다시 바이인할 때 받는 칩 |
| `TURN_SECS` | 30 | 한 차례에 주어지는 시간(초) |

## 구조

```
holdem/
├─ wrangler.jsonc          # Worker, 정적 파일, Durable Object, 테이블 규칙
├─ package.json            # npm run dev / build / deploy / check / test
├─ public/
│  └─ index.html           # 화면 마크업과 스타일 (app.js는 빌드 결과물)
├─ test/                   # workerd 안에서 도는 테스트
└─ src/
   ├─ shared/
   │  ├─ engine.ts         # 족보 판정 (서버와 클라이언트가 함께 사용)
   │  └─ protocol.ts       # WebSocket 메시지 형식, 프로토콜 버전
   ├─ server/
   │  ├─ worker.ts         # /lobby/ws → 로비, /ws/<코드> → 테이블, 나머지 → 정적 파일
   │  ├─ lobby.ts          # Durable Object: 방 목록 1개 (코드 발급, 상한, 빈 방 정리)
   │  ├─ table.ts          # Durable Object: 테이블 1개 (딜링, 베팅, 팟 정산, 타이머)
   │  └─ password.ts       # 방 비밀번호 솔트·해시
   └─ client/
      ├─ main.ts           # 테이블 화면, WebSocket 연결과 자동 재연결
      └─ lobby.ts          # 대기실 화면과 방 만들기
```

- **방은 로비를 통해서만 생깁니다.** 로비가 코드를 발급하고 테이블 객체를 초기화하므로, 주소창에 아무 코드나 쳐도 방이 만들어지지 않습니다. 초기화되지 않은 테이블은 접속을 거절합니다.
- 브라우저는 `/t/<코드>` 페이지를 열고 `/ws/<코드>`로 WebSocket을 연결합니다. Worker는 코드 이름으로 Durable Object 하나를 찾아 연결을 넘깁니다. 대기실은 `/lobby/ws` 하나로 연결합니다.
- 비밀번호는 솔트와 함께 SHA-256으로 저장하고, 평문은 보관하지 않습니다. **비밀번호를 통과하지 못한 연결은 테이블 상태를 한 줄도 받지 못하고, 인원수에도 좌석 정원에도 들어가지 않습니다.**
- 테이블 상태는 바뀔 때마다 Durable Object 저장소에 기록됩니다. 객체가 휴면하거나 재시작해도 이어서 진행됩니다.
- 턴 시간, 스트리트 사이 간격, 다음 핸드 시작은 모두 저장소 알람 하나로 처리합니다.
- 브라우저의 25초 간격 핑은 런타임이 자동으로 응답하므로 테이블 객체를 깨우지 않습니다.
- 메시지 형식을 바꿀 때는 `src/shared/protocol.ts`의 `PROTOCOL`을 올립니다. 배포 전에 열려 있던 탭은 새로고침 안내를 받습니다.

## 테이블 운영 규칙

- **이미 진행 중인 게임에 앉을 때는 둘 중 고릅니다.** 빅블라인드와 같은 금액을 내고 다음 핸드부터 바로 들어오거나, 버튼이 자기 자리를 지나갈 때까지 기다렸다 들어옵니다. 카드룸 규칙과 같고, 버튼 앞자리에 앉아 블라인드를 내지 않고 몇 핸드만 치고 나가는 걸 막습니다. 첫 핸드 전에는 아직 아무도 블라인드를 거를 수 없으므로 묻지 않습니다.
- **정규 레이즈에 못 미치는 올인은 레이즈를 다시 열지 않습니다.** 이미 행동한 사람은 추가 금액을 콜하거나 폴드할 수 있지만 다시 레이즈하지는 못합니다. 아직 행동하지 않은 사람은 그대로 레이즈할 수 있습니다. 최소 레이즈 폭도 정규 레이즈만 갱신합니다.
- 차례마다 `TURN_SECS`초 안에 행동하지 않으면 자동으로 체크하고, 콜해야 하는 상황이면 폴드합니다. 두 번 연속 시간을 넘기면 자리 비움으로 바뀝니다.
- 연결이 끊긴 플레이어는 20초 동안은 다음 핸드에 계속 포함되고, 그 뒤로는 빠집니다. 3분 넘게 돌아오지 않으면 다음 핸드가 시작될 때 자리가 정리됩니다.
- 칩을 모두 잃으면 '다시 바이인'으로 이어서 할 수 있습니다. 칩 현황의 손익은 바이인 횟수를 반영합니다.
- **빈 방은 정리됩니다.** 아무도 접속해 있지 않은 채 마지막으로 플레이한 지 15분이 지나면, 또는 만든 뒤 30분 동안 아무도 앉지 않으면 방이 사라집니다. 목록에서 빠진 방은 없어진 방이고, 그 주소로 들어가면 '없는 방입니다'가 나옵니다.

## 공개 링크로 운영할 때

- 무료 플랜은 한도(요청 하루 10만 건 등)를 넘으면 요금이 청구되지 않고 요청이 실패합니다.
- 서버는 모든 행동을 다시 검증합니다(차례, 최소 레이즈, 스택 한도). 이름은 플레이어 12자·방 20자로 자르고 제어 문자를 지웁니다. 접속당 5초에 30개를 넘는 메시지는 버립니다. 테이블당 접속은 60개까지 받고, 비밀번호를 기다리는 연결은 따로 10개까지 둡니다. 이 대기열이 차면 새 접속을 거절하는 대신 가장 오래 기다린 연결을 밀어냅니다 — 그렇게 하지 않으면 아무 말 없이 붙어 있는 소켓 몇 개로 방을 잠글 수 있습니다.
- 대기실은 누구나 보고 누구나 들어옵니다. 그래서 상한을 둡니다: 서버 전체 30개, 한 주소가 동시에 가질 수 있는 방 3개, 한 주소가 분당 만들 수 있는 방 3개, 대기실 접속 200개.
- 비밀번호를 5번 틀리면 그 주소는 1분 기다려야 하고, 계속 틀리면 최대 15분까지 늘어납니다. 재접속해도 초기화되지 않습니다.
- 로그인이 없으므로 플레이어 구분은 브라우저에 저장된 무작위 토큰으로 합니다. 다른 브라우저로 들어오면 다른 사람으로 취급됩니다. 토큰은 브라우저가 들고 있는 값이라 상한의 기준으로는 쓰지 않고, 접속 주소를 씁니다.

## 점검 명령

```bash
npm run check   # 서버와 클라이언트 타입 검사
npm test        # 실제 workerd 런타임에서 도는 테스트
```

`npm install`이 `Cannot read properties of null (reading 'edgesOut')`으로 실패하면 npm 10의 알려진 버그입니다. `.npmrc`에 그 우회 설정이 들어 있으니 보통은 그대로 설치됩니다. npm 12 이상에서는 필요 없습니다.
